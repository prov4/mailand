# mailand

A fast, keyboard-driven mail, calendar and contacts app for Hyprland / Wayland, built for Omarchy. It has no GNOME, GTK or Electron dependencies.

**Version 0.2.0**: mail (IMAP/SMTP, Gmail via OAuth2), calendars (CalDAV) and contacts (CardDAV).

mailand is two programs:

| Program | Language | What it does |
| --- | --- | --- |
| `mailand-daemon` | Go | Runs in the background as a `systemd --user` service. Syncs mail over IMAP (with IDLE push), calendars over CalDAV and contacts over CardDAV, sends over SMTP, stores everything in SQLite with full-text search, keeps passwords and tokens in the system keyring, and serves a gRPC API on `$XDG_RUNTIME_DIR/mailand.sock`. |
| `mailand-ui` | C++20, Qt 6 / QML | The window you use: Mail, Calendar and Contacts views, driven from the keyboard. HTML mail is shown in a locked-down WebEngine view: no JavaScript, and remote images stay blocked until you allow them. |

The UI is only a view. Closing it doesn't stop syncing, and the daemon keeps mail current even when no window is open.

## Quick start

On Arch / Omarchy:

```sh
# 1. Tools and libraries
sudo pacman -S --needed go cmake protobuf grpc git \
    qt6-base qt6-declarative qt6-wayland qt6-webengine gnome-keyring

# 2. Get the code and build
git clone <this repository> mailand && cd mailand
make

# 3. Install as a package and start the daemon
make package            # use `make package MAKEPKG_FLAGS=-d` if Go comes from mise/asdf
sudo pacman -U deploy/mailand-git-[0-9]*.pkg.tar.zst
make enable-daemon

# 4. Add an account (see "Setting up accounts"), log in, restart the daemon
$EDITOR ~/.config/mailand/config.toml
mailand-daemon login gmail
systemctl --user restart mailand-daemon
```

Then open **Mailand** from the app launcher.

## Requirements

| Need | Arch package | Notes |
| --- | --- | --- |
| Go ≥ 1.26 | `go` | Or through mise: the repo pins Go in `mise.toml`, so `mise install` sets it up. |
| CMake ≥ 3.24 | `cmake` | |
| C++20 compiler | `gcc` (base-devel) | |
| Qt ≥ 6.5 | `qt6-base qt6-declarative qt6-wayland qt6-webengine` | |
| gRPC + Protobuf | `grpc protobuf` | Code for the UI is generated by CMake at build time. |
| A Secret Service keyring | `gnome-keyring` | KWallet or KeePassXC work too. One must run on the session D-Bus. |
| git | `git` | Used for the package version. |

`make proto` (regenerating the Go gRPC code after editing `proto/mailand.proto`) also needs `protoc`, which comes with `protobuf`. It installs the Go protoc plugins into `.tools/` on first use.

## Building from source

```sh
make          # everything, debug build:
              #   build/bin/mailand-daemon, build/bin/mailand-seed, build/frontend/mailand-ui
make test     # Go test suite
make release  # optimised binaries in build/release/ (what `make install` ships)
make version  # print the version (from the VERSION file)
make clean    # remove build/
```

Check what you built:

```sh
build/bin/mailand-daemon version     # mailand-daemon 0.2.0
build/frontend/mailand-ui --version  # mailand-ui 0.2.0
```

The version comes from the single `VERSION` file at the repository root. The Go build (`-ldflags -X main.version`), CMake and the PKGBUILD all read it. To release, edit `VERSION`.

## Trying it without an account

The seed tool writes a realistic sample database: two accounts, about 400 messages (including HTML newsletters, attachments and inline images), three calendars with recurring and all-day events around today, and 14 contacts. The daemon can serve it without touching the network:

```sh
make
build/bin/mailand-seed                 # writes ~/.local/share/mailand (add -force to replace it)
build/bin/mailand-daemon -offline &    # serves the store; no IMAP/CalDAV, changes stay local
build/frontend/mailand-ui
```

Run this only while the systemd service is stopped, because both use the same socket and data directory. To keep the sample data apart from your real mail, point everything at a scratch location:

```sh
export XDG_DATA_HOME=/tmp/mailand-demo MAILAND_SOCKET=$XDG_RUNTIME_DIR/mailand-demo.sock
```

## Installing

### Option A: Arch package (recommended)

```sh
make package                               # builds deploy/mailand-git-<version>-x86_64.pkg.tar.zst
sudo pacman -U deploy/mailand-git-[0-9]*.pkg.tar.zst
make enable-daemon                         # systemctl --user daemon-reload && enable --now mailand-daemon
```

The package builds from your local checkout, including uncommitted changes. It installs:

```
/usr/bin/mailand-daemon
/usr/bin/mailand-ui
/usr/lib/systemd/user/mailand-daemon.service
/usr/share/applications/mailand-ui.desktop
/usr/share/icons/hicolor/scalable/apps/mailand.svg
```

If `makepkg` stops with **"Missing dependencies: go"**, your Go comes from mise or asdf rather than pacman. Build with `make package MAKEPKG_FLAGS=-d`.

To update later: `git pull`, run the same three commands again, then `systemctl --user restart mailand-daemon`.

### Option B: `make install`

```sh
sudo make install          # PREFIX=/usr by default; DESTDIR is honoured
make enable-daemon
```

Remove it with `sudo make uninstall`.

### The daemon service

`mailand-daemon` is a **user** service. Always pass `--user` and never use `sudo`:

```sh
systemctl --user status mailand-daemon
systemctl --user restart mailand-daemon
journalctl --user -u mailand-daemon -f      # live log
```

(`systemctl status mailand-daemon` without `--user` reports "could not be found". That's expected.)

The unit is sandboxed: the file system is read-only except `~/.local/share/mailand` and `$XDG_RUNTIME_DIR`, with no new privileges and a system-call allow-list. If you use a custom `XDG_DATA_HOME`, adjust `ReadWritePaths` and `ExecStartPre` with `systemctl --user edit mailand-daemon`.

## Setting up accounts

Accounts live in `~/.config/mailand/config.toml` (override with `$MAILAND_CONFIG`). **No secrets go in this file.** Passwords and OAuth tokens are stored in the keyring, and the daemon refuses keys like `password` or `token` in the config.

### Gmail (OAuth2): mail, calendar and contacts

Google requires your own OAuth client. You set it up once:

1. In [Google Cloud Console](https://console.cloud.google.com/), create a project.
2. Under **APIs & Services → Library**, enable:
   - **Gmail API**
   - **CalDAV API** (calendars)
   - **Google Contacts CardDAV API** (contacts)
3. Under **OAuth consent screen**, choose *External*, fill in the app name and your email, and add these scopes:
   - `https://mail.google.com/`
   - `https://www.googleapis.com/auth/calendar`
   - `https://www.googleapis.com/auth/carddav`
4. Set the **publishing status to *In production***. While it stays in *Testing*, Google expires your login every 7 days. An unverified personal app is fine; you click through the "unverified app" warning once.
5. Under **Credentials**, create an **OAuth client ID** of type **Desktop app**, and note its client ID and secret.
6. In Gmail settings, under **Forwarding and POP/IMAP**, enable IMAP. Under **Labels**, tick **Show in IMAP** for **All Mail**. mailand syncs All Mail once and builds the labels from it.

Then write the config:

```toml
[google]
client_id = "1234567890-abc.apps.googleusercontent.com"
client_secret = "GOCSPX-..."        # Google does not treat desktop-app secrets as confidential

[[account]]
id = "gmail"                        # stable id: [a-z0-9_-]+, unique
name = "Personal Gmail"
email = "someone@gmail.com"
provider = "gmail"
# poll_interval = "5m"              # how often non-INBOX folders are checked (INBOX is push)
# caldav_url = "off"                # disable calendar sync for this account
# carddav_url = "off"               # disable contacts sync for this account
```

Log in. This opens your browser and stores the refresh token in the keyring:

```sh
mailand-daemon login gmail
systemctl --user restart mailand-daemon
```

Calendars and contacts use the same login. If you logged in with an older mailand version, or added the CalDAV/CardDAV APIs after logging in, run `mailand-daemon login gmail` once more.

### Other providers (IMAP + password; CalDAV/CardDAV optional)

```toml
[[account]]
id = "work"
name = "Work"
email = "me@example.com"
provider = "imap"
imap_host = "imap.example.com"     # port 993, implicit TLS by default
smtp_host = "smtp.example.com"     # port 465, implicit TLS by default
# imap_tls = "starttls"            # then the port defaults to 143
# smtp_tls = "starttls"            # then the port defaults to 587
caldav_url = "https://dav.example.com/"     # optional: server root, principal or calendar URL
carddav_url = "https://dav.example.com/"    # optional: server root, principal or address book URL
```

```sh
mailand-daemon set-password work   # prompts; stored in the keyring
systemctl --user restart mailand-daemon
```

The same login (`email` + keyring password) is used for IMAP, SMTP, CalDAV and CardDAV. For the DAV URLs, the server root is usually enough: mailand looks up your principal, then the calendar or address-book home, then the collections. If discovery fails it treats the URL as a single calendar or address book. Standards-compliant servers (Fastmail, Nextcloud, Radicale, Baïkal and similar) should work. Only Google's endpoints and an in-process test server have been exercised so far, so please report servers that don't.

## Using mailand

Open **Mailand** from the launcher, or run `mailand-ui`. Switch views with the buttons at the bottom of the sidebar or with **Ctrl+1 / 2 / 3**. Press **?** at any time for the shortcut list.

### Mail

A three-pane layout: folders, messages, reader. Search with `/` (full text, accent-insensitive, prefix matching). **Send/Receive** at the top of the sidebar (or `Ctrl+R` / `F5`) checks every account for new mail, calendar and contact changes right away. Otherwise new mail arrives by IMAP IDLE push.

The first sync of a large mailbox downloads newest first, 500 messages at a time. The status bar shows how many are left, and new mail still arrives in between.

### Composer

`c` new message, `r` reply, `R` reply all, `f` forward. Replies quote the original and set `In-Reply-To`/`References`, so threads stay together. **Address autocomplete**: start typing a name or address in To/Cc/Bcc, pick with ↑/↓, and accept with Enter or Tab. `Ctrl+Enter` sends. Sent mail is stored in your Sent folder.

### Calendar

A month grid (weeks start on Monday) with an agenda for the selected day. It shows events from all accounts: recurring events (including exceptions and cancelled occurrences), all-day and multi-day events, in your local time zone. Click a calendar in the sidebar to hide or show it.

`h`/`l` previous/next day · `k`/`j` previous/next week · `p`/`n` previous/next month · `t` today

The calendar is read-only in 0.2.0: create and edit events in your provider's app for now.

### Contacts

A searchable list (name, email or organization) and a detail panel. `j`/`k` move, `/` searches, `c` or Enter writes an email to the selected contact. Clicking an email address does the same.

## Troubleshooting

Start with the log: `journalctl --user -u mailand-daemon -f`. Each sync pass logs a `sync pass done` line, and calendars and contacts log `calendar sync done` / `contacts sync done`.

| Symptom | Fix |
| --- | --- |
| `Unit mailand-daemon.service could not be found` | You left out `--user`: `systemctl --user status mailand-daemon`. |
| `makepkg`: Missing dependencies: go | `make package MAKEPKG_FLAGS=-d` (Go from mise/asdf). |
| "Daemon not connected" in the status bar | The daemon isn't running: `systemctl --user start mailand-daemon`, then check the journal. |
| Keyring errors / "secret not found" | Check that a Secret Service runs and is unlocked: `busctl --user list \| grep secrets`. Start one with `gnome-keyring-daemon --start --components=secrets`, then run `mailand-daemon login <id>` again. |
| Gmail shows no mail | Gmail settings → Labels → **Show in IMAP** for **All Mail**. |
| Red banner "needs re-authentication" / `reauth_required` | Google revoked or expired the token (consent screen in *Testing*, password change). Run `mailand-daemon login <id>`, then press Send/Receive. |
| `calendar: access denied (403)` or `contacts: access denied (403)` | Enable the **CalDAV API** / **Google Contacts CardDAV API** in Cloud Console, check the scopes on the consent screen, then run `mailand-daemon login <id>` again. |
| Calendar or contacts empty for a non-Google account | Check `caldav_url` / `carddav_url`. Try the server's documented DAV URL, then look at the journal for the discovery error. |
| High CPU during the first sync | Expected while a large mailbox downloads (parsing and indexing). The status bar shows the messages left. After that the daemon is idle. |
| Config errors | The journal names the exact key and line. Unknown keys and secret-like keys are rejected. |
| "address already in use" | Another daemon owns the socket. Stop the service before running one by hand. |

## Development

```
proto/mailand.proto        single source of truth for the daemon <-> UI API
backend/                   Go module (mailand-daemon, mailand-seed)
  cmd/mailand-daemon       entry point, `login`/`set-password`/`version` subcommands
  internal/config          config.toml loader and validation
  internal/auth            Google OAuth2 (loopback + PKCE), keyring, XOAUTH2
  internal/store           SQLite schema + migrations, FTS5 search
  internal/mail            IMAP sync (IDLE, CONDSTORE, Gmail labels), MIME parsing
  internal/send            message composition, SMTP, Sent-folder APPEND
  internal/dav             CalDAV/CardDAV sync, iCalendar recurrence expansion
  internal/rpc             gRPC server and event broker
frontend/                  Qt 6 / QML UI (CMake)
  src/                     Rpc client, list models, composer, WebEngine glue, self-test
  qml/                     views and components
deploy/                    systemd unit, .desktop file, icon, PKGBUILD
VERSION                    the version, read by every build
```

Useful loops:

```sh
make test                                   # Go tests (sync engines against in-process IMAP/CalDAV/CardDAV servers)
make proto                                  # after editing proto/mailand.proto
build/bin/mailand-daemon -offline &         # serve seeded data
build/frontend/mailand-ui --selftest        # headless end-to-end check against the running daemon
build/frontend/mailand-ui --screenshot out.png --view calendar   # render a view offscreen
```

`--screenshot` also takes `--open-first`, `--open-composer new|reply|replyAll|forward` and `--delay ms`. Set `QT_QPA_PLATFORM=offscreen` to run without a display.
