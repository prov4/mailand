# mailand

A keyboard-driven mail client for Hyprland/Wayland (built for Omarchy). It is two programs:

- `mailand-daemon`: Go backend. Syncs IMAP (with IDLE), stores mail in SQLite, sends via SMTP, keeps secrets in the Secret Service keyring, and serves a gRPC API on `$XDG_RUNTIME_DIR/mailand.sock`.
- `mailand-ui`: Qt 6 / QML three-pane UI that talks to the daemon over that socket. HTML mail is shown in a locked-down WebEngine view (no JavaScript, remote images blocked until you ask).

Gmail (OAuth2) is the primary target; other IMAP providers work with a password stored in the keyring. Calendar/contacts (CalDAV/CardDAV) are not implemented yet.

## Requirements

Arch packages:

```
sudo pacman -S --needed go cmake protobuf grpc git \
    qt6-base qt6-declarative qt6-wayland qt6-webengine gnome-keyring
```

Any Secret Service provider (gnome-keyring, KWallet, KeePassXC) works in place of `gnome-keyring`. The daemon needs one running on the session D-Bus.

## Build from source

```
make            # Go daemon + seed tool -> build/bin/, Qt UI (Debug) -> build/frontend/mailand-ui
make test       # Go tests
make proto      # regenerate Go protobuf code (C++ code is generated by CMake)
```

## Development loop

Run the UI against sample data without any account or network:

```
make
build/bin/mailand-seed            # writes a sample DB into ~/.local/share/mailand (use -force to overwrite)
build/bin/mailand-daemon -offline # serves the store, no IMAP; flag changes are local only
build/frontend/mailand-ui
```

`make run-daemon` builds and starts the daemon (online) from the tree. Do not run it alongside the systemd service: both bind the same socket. Override with `-socket PATH` or `MAILAND_SOCKET`.

## Gmail setup

1. In Google Cloud Console, create a project and enable the Gmail API (plus CalDAV/CardDAV if you plan to use them later).
2. Configure the OAuth consent screen and create an OAuth client ID of type **Desktop app**.
3. Add the scopes `https://mail.google.com/`, `https://www.googleapis.com/auth/calendar` and `https://www.googleapis.com/auth/carddav`.
4. Set the publishing status to **In production**. While it is in *Testing*, Google expires refresh tokens after 7 days. An unverified personal app is fine; click through the "unverified app" warning once.
5. In Gmail settings, under Forwarding and POP/IMAP, make sure IMAP is enabled and that **All Mail is shown in IMAP** (see Troubleshooting).

### config.toml

`~/.config/mailand/config.toml` (or `$MAILAND_CONFIG`). Secrets are rejected in this file; they live in the keyring.

```toml
[google]
client_id = "1234567890-abc.apps.googleusercontent.com"
client_secret = "GOCSPX-..."

[[account]]
id = "gmail"                  # stable id: [a-z0-9_-]+, unique
name = "Personal Gmail"
email = "someone@gmail.com"
provider = "gmail"            # "gmail" | "imap"
# auth = "oauth2_google"      # default for gmail; "password" for other providers
# poll_interval = "5m"        # secondary-folder polling

# Plain IMAP account (host fields required; tls "implicit" or "starttls"):
# [[account]]
# id = "work"
# email = "me@example.com"
# provider = "imap"
# imap_host = "imap.example.com"
# smtp_host = "smtp.example.com"
```

Log in (opens your browser, stores the refresh token in the keyring):

```
mailand-daemon login gmail          # the account id from config.toml
mailand-daemon set-password work    # for auth = "password" accounts
```

## Install and run with systemd

Option A, Arch package (builds from the local working tree, including uncommitted changes):

```
make package
sudo pacman -U deploy/mailand-git-*.pkg.tar.zst
make enable-daemon    # systemctl --user daemon-reload && systemctl --user enable --now mailand-daemon
```

Option B, install files directly (`PREFIX`/`DESTDIR` supported, default `PREFIX=/usr`):

```
sudo make install
make enable-daemon
```

Then launch **Mailand** from your launcher, or run `mailand-ui`. Logs: `journalctl --user -u mailand-daemon -f`. Hyprland window class is `mailand-ui`, e.g. `windowrule = float, class:^(mailand-ui)$`.

The unit is sandboxed (`ProtectSystem=strict`, `ProtectHome=read-only`). It can write only `~/.local/share/mailand` and `$XDG_RUNTIME_DIR`, so a custom `XDG_DATA_HOME` needs a drop-in (`systemctl --user edit mailand-daemon`) adjusting `ReadWritePaths` and `ExecStartPre`.

## Keybindings

| Key | Action |
| --- | --- |
| `j` / `k` | Next / previous message (opens it) |
| `Enter` / `l` | Focus reader pane |
| `h` / `Esc` | Back to message list |
| `/` | Search |
| `g g` / `G` | First / last message |
| `J` / `K` | Next / previous folder |
| `c` | Compose |
| `r` / `R` | Reply / reply all |
| `f` | Forward |
| `Ctrl+Enter` | Send (in the composer) |
| `Esc` | Close the composer |
| `m` | Toggle read / unread |
| `s` | Toggle star |
| `Ctrl+R` / `F5` | Sync current account |
| `?` | Help overlay |
| `Ctrl+Q` | Quit |

The in-app `?` overlay is the authoritative list.

## Troubleshooting

- **Keyring not running / "secret not found"**: the daemon reads tokens from the Secret Service on the session D-Bus. Check `busctl --user list | grep secrets`; start `gnome-keyring-daemon --start --components=secrets` (or your provider) and unlock it, then `systemctl --user restart mailand-daemon`. Re-run `mailand-daemon login <id>` if the entry is missing.
- **Gmail shows no mail / All Mail empty**: mailand syncs from `[Gmail]/All Mail` and builds labels from it. In Gmail, Settings, Labels, enable "Show in IMAP" for **All Mail** (also Spam and Trash if you want them).
- **`reauth_required`**: Google revoked or expired the refresh token (typical when the consent screen is still in *Testing*, or after a password change). Sync for that account stops and the UI shows a banner. Run `mailand-daemon login <id>`, then press `Ctrl+R` to resume sync.
- **Config errors**: `journalctl --user -u mailand-daemon` shows the exact key and line. Unknown keys and secret-like keys (`password`, `token`, `secret`) are rejected in account tables.
- **"address already in use" / second daemon**: stop the service (`systemctl --user stop mailand-daemon`) before running one by hand.
